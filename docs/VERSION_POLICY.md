# Canonical Semantic Versioning policy

Root `VERSION` is the single project version. The user approved canonical development target **0.17.0** on 2026-10-16 after review of observed source mirrors at **0.16.1**. The initial Git import preserves that observed 0.16.1 baseline; it is not a stable release. The approved pre-1.0 MINOR iteration records the renamed activation identity, removed renderer capability, corrected dependency integration and repository onboarding. Save/schema versions do not change.

Before implementation, classify the change and record the target version. PATCH means a compatible correction; MINOR means a compatible feature or a pre-1.0 public-contract/behavior change; MAJOR means an incompatible public contract once the mod reaches 1.0.0. Discuss ambiguous compatibility changes before choosing a version. Use valid SemVer; numeric prerelease identifiers cannot have leading zeroes. Do not confuse game, dependency, schema, protocol or framework versions with project version.

Exact current version-bearing mirrors and their anchored selectors are declared in `docs/VERSION_MIRRORS.json`. Run `python scripts/check_versions.py` before/after edits. Update every current mirror and the newest CHANGELOG heading together. The source fingerprint manifest is current evidence and must be regenerated for source changes. Historical records and immutable released packages retain their original versions/hashes, classified by the source inventory; never rewrite them to appear current.

The public source root and authoring assets are declared in `docs/SOURCE_INVENTORY.json`. `Contents`, `dist`, old checksums, ignored local history/reports and the retired JAR are not package inputs. No current package exists. Future packaging needs explicit authorization and a new clean staging area, package integrity checks and provenance binding version, Mod ID, Workshop ID, commit, source/package hashes and exact runtime evidence.

Run `python scripts/check_versions.py --release` before G8. It currently fails closed because current release artifacts/provenance workflow and dedicated G7 PASS do not exist. Source-version consistency does not authorize a release. An explicitly requested future Workshop MP test build remains subject to the global test-distribution policy; dedicated G7 and stable G8 stay blocked until genuine runtime evidence exists.

Use feature/fix branches and PRs before shared-main merges. Every intentional development iteration must be committed and pushed to the configured PUBLIC repository after staged-file review, credential/artifact checks, fresh ancestry and applicable tests. Verify remote SHA. Do not force-push, rewrite history, create stable tags without release approval, or infer deployment/Workshop publication from a GitHub push.
